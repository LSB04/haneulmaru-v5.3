하늘마루 V5.4 — 분산 배치 / 합류 5초 / 발표 근거

1. 문제와 수정
이전에는 반지름 200의 원 둘레에만 20개 슬롯을 배치하여 미니맵 중앙에 작은 고리처럼 보였습니다.
이번에는 내부까지 채우는 5열×4행 격자로 바꾸었습니다. 슬롯 간격은160, 초기 배치 폭640×깊이480 좌표단위입니다.
미니맵 축척은 그대로 유지하여 실제 3D 배치와 동일한 좌표를 보여줍니다.
새 파랑은 기존 객체의 자리를 바꾸지 않고 빈 슬롯에5초 동안 합류합니다.
각속도는0.006 rad/s, 외곽 반경은400이므로 가장 바깥 슬롯 속도는2.4 좌표단위/s입니다.
안쪽 슬롯은 더 느리며, 전체 회전 주기는 약17분27초입니다.
자동 생성은 최초8초 뒤, 이후14초 간격이며 자유 궤도 객체는 기존 절반 속도를 유지합니다.
시간은 재생 배속1 기준의 시뮬레이션 시간입니다.

2. 간격이 유지되는 이유
슬롯 k=0..19, 열 c=k mod5, 행 r=floor(k/5).
초기 좌표 qk=(160(c−2),160(r−1.5)). 공통 표시 고도를 사용합니다.
θ=0.006t일 때 x=x0 cosθ−z0 sinθ, z=x0 sinθ+z0 cosθ.
모든 슬롯에 같은 회전행렬 R을 적용합니다. RᵀR=I이므로 ||R(qi−qj)||=||qi−qj||.
따라서 모든 슬롯 사이의 거리가 유지되고, 완성된 격자의 최소 간격은160입니다.
일부 객체가 없어지면 빈 슬롯만 남습니다. 슬롯을 재배치하지 않아 기존 객체가 갑자기 움직이지 않습니다.
반경과 간격은 시연 가독성을 위한 설계값이며 최적 배치나 탐지 범위를 의미하지 않습니다.

3. 5초 합류
u=clamp(합류 경과시간/5,0,1), s=3u²−2u³.
표시 위치=(1−s)×분류 시점 위치+s×현재 슬롯 위치.
자동 배치에서 합류 완료 후에만 슬롯 간격이 유지됩니다.
합류 도중, 수동 조작, 게임 충돌 연출에는 간격 보장이 적용되지 않습니다.
실제 비행 제어·장애물 회피·안전성 검증 기능은 아닙니다.

4. 왜 가까운 파랑을 사용하는가 — 현재 코드의 정확한 설명
합성 게임 이벤트에서는 이미 다른 이벤트에 참여한 파랑을 제외하고,
현재 화면상 3차원 직선거리가 가장 짧은 파랑을 선택합니다.
멀리 있는 객체가 갑자기 화면을 가로지르는 연출을 줄이기 위한 단순 거리 기준입니다.
최대20개의 후보를 한 번 비교하므로 후보 선택 연산량은 O(N)입니다.

이 기준을 실제 경제성·배터리 비용 최적화라고 설명하면 안 됩니다.
현재 프로그램은 배터리 소모·전력·기체 가격·장애물 우회·가속도·성공 확률을 계산하지 않습니다.
특히 충돌 이동은 기존 1초짜리 화면 연출이므로, 거리가 짧다고 도달시간이 짧아지는 모델도 아닙니다.
발표 시에는 '비용 최적화를 완료했다' 대신 '현재는 이동 거리만 고려한 단순 게임 기준선이며,
실제 비용 절감 효과는 측정하지 않았다'고 설명하는 것이 정확합니다.
실제 카메라/YOLO 탐지 결과가 이 게임 이벤트의 입력으로 사용되지 않습니다.

5. 발표용 설명
“작은 원 둘레에 몰리던 가상 객체를 5×4 격자로 분산했습니다.
모든 슬롯을 같은 회전행렬로 움직여 합류 완료 후 간격160을 유지합니다.
새 객체는5초간 빈 슬롯으로 부드럽게 합류하고, 기존 객체의 자리는 유지합니다.
배치 간격과 속도는 화면 가독성을 위한 값이며 실제 비행 안전성이나 비용 최적성을 검증한 것은 아닙니다.”

7. AR 복구
V5.4 AR 앱에서 카메라 합성을 복구했습니다. PC는 선택한 드론과 현재 시점으로 가상 객체만 별도 렌더링합니다.
휴대폰은 PC 영상의 자홍색 배경을 제거하고 로컬 카메라 위에 합성합니다.
추적/탑승 시점과 터치/NU40 입력은 기존 가상 카메라를 공유합니다.
실제 공간의 위치/평면/가림을 추적하는 ARCore 앵커 방식은 아닙니다.
카메라 권한이 없는 기존 V5.3 앱은 가상환경 연결만 지원합니다. 새 V5.4 AR APK를 설치하세요.
