하늘마루 V5.3 — 인터넷 없는 로컬 H.264 영상 스트리밍

1. PC: 하늘마루_실행.cmd 실행. 이 폴더는 V5.1/V5.2와 별개입니다.
2. 처음 한 번 로컬망_방화벽.ps1을 실행해 Windows 관리자 허용을 완료합니다.
   PC 내부 웹 8800 / 폰 HTTPS 8801 / 앱 다운로드 8802 / 영상 WSS 8803.
   방화벽은 이 PC의 Python 프로그램과 같은 로컬 서브넷에만 허용합니다.
3. 앱 이름: 하늘마루 V5.3 LAN
   설치 파일: android-usb/dist/haneulmaru-v53-lan.apk
   기존 V5.2 앱과 별도로 설치됩니다. PC 첫 번째 QR로 다운로드합니다.
4. 휴대폰 데이터는 끄고 핫스팟을 켠 뒤, 노트북을 그 핫스팟에 연결합니다.
   네트워크를 바꾸었으면 실행.cmd를 다시 실행해 IP와 QR을 갱신합니다.
5. PC 두 번째 QR의 전체 연결 주소를 V5.3 앱에 입력 → 로컬 연결 → PC 연결 시작.
   기본은 H.264 지속 영상 스트림입니다. USB 연결 버튼은 NU40 센서용입니다.
   PC 지형 창은 최소화하지 마세요. GPU를 분리했다면 창을 닫고 다시 실행합니다.
6. 화면에 H.264 영상 FPS와 인코딩 정보가 표시됩니다.
   '실시간 1920 / 60 FPS'는 상한이며 휴대폰/무선 상태에 따라 실제 FPS가 달라집니다.
   렉이 생기면 '선명 1920 / 30 FPS' 또는 '균형 1280 / 24 FPS'를 선택합니다.
7. WebCodecs를 지원하지 않는 Android WebView에서는 WebRTC 연결 버튼을 사용합니다.
   마지막 수단인 로컬 호환 연결은 V5.2 방식(JPEG 최대 10FPS)입니다.

새 통신 방식
PC GPU 렌더링 → VideoFrame → WebCodecs H.264 → 로컬 WebSocket 릴레이
→ 로컬 TLS(WSS) → 휴대폰 VideoDecoder → 화면.
조작은 영상과 별도의 지속 소켓으로 보내며 매번 HTTP 응답을 기다리지 않습니다.
인코딩 대기열/전송 버퍼를 제한하고, 밀린 영상은 키프레임부터 다시 동기화합니다.
RAW 무압축 전송은 아니며, JPEG 한 장씩 압축하고 폴링하는 구조를 대체합니다.
TCP 재전송 지연이 발생할 수 있어 WebRTC보다 모든 네트워크에서 빠르다는 보장은 없습니다.

Local + CLIKA 유지
model-selection.json: Qwen/Qwen3.5-2B, ClikaRT 0.6.4.
모델은 PC에서 자연어 장면 설정에 사용합니다. 3D 렌더링과 영상 압축은 별도입니다.
V5.2의 모델 파일은 V5.3에 복사했으며 새 양자화나 모델 교체는 수행하지 않았습니다.
라이선스는 기존 로컬 파일/환경변수를 사용합니다. APK에는 모델이나 라이선스가 없습니다.
이번 검증은 영상 통신 검증입니다. CLIKA의 오프라인 추론 성공 또는 대회 우대조건
충족을 대신 증명하지 않습니다. 모델 응답과 심사 기준은 별도로 확인해야 합니다.

검증 자료
output/transport-benchmark.json: 같은 PC의 실제 장면/인코더/디코더 비교.
output/live-tls-check.json: 실제 사설 IP + TLS 포트의 영상/조작 및 GPU 사용률 확인.
성능비교_V5.3.txt: 위 결과를 요약한 비교표.
물리적 휴대폰, 핫스팟 무선 구간, 모바일 WebView 호환성은 사용자 기기에서 추가 확인합니다.

종료: 서버 PowerShell 창에서 Ctrl+C 또는 종료_V5.3.ps1 실행.
외부 공유 시 .local-tls, android-usb/.keys, output/브라우저 프로필, 라이선스는 제외합니다.
